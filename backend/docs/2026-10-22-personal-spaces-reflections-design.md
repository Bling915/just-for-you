# 个人空间与双人回忆体验设计

日期：2026-10-22
状态：已完成会话设计评审，等待书面规格确认

## 1. 背景与目标

“小事成双对”当前以情侣共同记录为核心。此次改版在不削弱双方小日记主线的前提下，增加属于个人的记录空间，并把记录、回应和回顾串成完整体验：

1. 用户可以把小事发布到共同空间或个人空间。
2. 个人小事可以仅自己可见，也可以主动分享给当前伴侣。
3. 对方可以用轻量回应和独立视角参与共同回忆。
4. 每日一句用低压力的方式推动交流，双方回答后才互相解锁。
5. “那天的我们”让已经记录的小事在合适的时间重新出现。
6. 全部页面使用统一的手账漂浮动效，同时提供减少动态效果降级。

成功标准是：空间归属和隐私范围始终清晰；历史共同小事无感迁移；关系解绑后个人记录仍归本人；AI 不能接触“仅自己”的内容；新增体验仍围绕“小事记录”而不是演变为聊天或社交平台。

## 2. 功能边界

本次包含：

- 我们的小事、我的小事、TA 的小事三个浏览入口。
- 发布时选择共同空间或个人空间。
- 个人空间的“仅自己”和“对方可见”权限。
- 从个人小事创建关联的“分享给我们”记录。
- 小事轻量回应。
- 所有共同小事的双视角补充。
- AI 个性化每日一句及内置题库降级。
- 双向回答解锁与共同回答卡。
- “那天的我们”回忆推荐。
- 统一组件、动效 token 和减少动态效果。

本次不包含：

- 即时聊天、语音或视频通话。
- 多人家庭空间或好友社交。
- 把个人小事直接移动为共同小事。
- AI 读取图片、精确位置或“仅自己”内容。
- 完整端到端加密。隐私边界会按未来可升级加密的方式设计，但不在本期实现。

## 3. 产品与交互设计

### 3.1 空间入口

首页提供两个主要入口：

- “我们的小事”：展示双方共同发布的记录。
- “我的小事”：展示当前用户的全部个人记录。

点击伴侣头像进入“TA 的小事”，只展示伴侣标记为“对方可见”的个人记录。入口采用当前薰衣草暖色体系，不创建三套完全割裂的视觉系统。

### 3.2 发布流程

发布页默认选中“我们的小事”，延续产品的共同记录主线。切换到“我的小事”后显示可见范围选项，并默认“仅自己”。发布按钮使用明确文案：

- `发布到我们的小事`
- `仅自己保存`
- `分享给 TA`

共同空间只允许 `couple` 可见性；个人空间只允许 `private` 或 `partner`。非法组合由后端拒绝。

### 3.3 分享给我们

个人小事支持“分享给我们”。该操作不移动或修改原记录，而是在共同空间创建一条关联记录。用户可以补充一句想对伴侣说的话。原个人记录继续保留原可见范围，避免分享操作改变私人原稿。

### 3.4 轻量回应

对方可见的小事支持“看到啦”“抱抱你”“想和你一起”“收藏进我们的回忆”和一条最多 120 个 Unicode 字符的短文本回应。回应不是公开评论区：只面向情侣双方，同一用户的同种预设回应保持幂等。

### 3.5 双视角回忆

每条共同小事允许另一方补充一次“我的视角”，包含文字和最多三张照片。原作者维护原始内容，补充者维护自己的视角，任何一方不能编辑或删除对方的内容。两份内容在同一张双视角卡中组合展示，并可用于纪念海报。

### 3.6 每日一句

每天每对情侣只有一道题：

- 双方独立回答，提交前看不到对方答案。
- 一方提交后只显示“等待 TA 回答”。
- 双方提交后同时解锁，并生成共同空间双人回答卡。
- 自己的答案在解锁前可以修改；双方解锁后答案冻结，避免对方看过后被悄悄改写。
- 不设置连续签到惩罚，历史问题允许补答。

AI 个性化默认可在设置中关闭。关闭、AI 超时、额度不足或输出不合规时，系统使用内置精选题库，不让首页出现阻塞状态。

### 3.7 那天的我们

首页在存在合适内容时展示一张回忆卡，候选来源包括一个月前、去年今日、相同地点、纪念日前后和首次共同记录。回忆不是强制每日出现；没有合适内容时不展示空卡。

### 3.8 视觉与动效

整体采用“手账漂浮感”：卡片轻微错位和旋转、纸张层叠、新卡片柔和上浮、发布成功使用贴纸式弹跳。照片采用轻微拍立得边框。纪念日与回忆海报可以少量使用电影相册式转场。

动效由统一 token 控制，至少包含时长、缓动、位移、旋转和阴影等级。开启“减少动态效果”时，取消循环漂浮、旋转和弹跳，只保留不超过 160ms 的淡入。动画加载失败不得影响页面操作。

## 4. 领域模型

### 4.1 Moment 扩展

`Moment` 增加：

- `space_type`: `shared | personal`
- `visibility`: `couple | private | partner`
- `kind`: `standard | daily_question`
- `source_moment_id`: 可空；“分享给我们”生成的记录指向来源
- `daily_question_id`: 可空；双人回答卡指向已解锁的问题

领域不变量：

- `shared` 必须搭配 `couple`。
- `personal` 必须搭配 `private` 或 `partner`。
- 只有作者可以编辑、删除自己的 Moment 或改变个人记录可见范围。
- `partner` 只对当前关系中的伴侣可见；解绑后立即失效。
- 分享生成新的共同记录，不改变源记录。
- `daily_question` Moment 只能由系统在双方答案解锁时创建，必须属于共同空间且关联一个问题。

### 4.2 Perspective

`MomentPerspective` 包含共同小事 ID、作者、文字、最多三张照片和时间。数据库约束保证每位用户对同一共同小事最多一份视角。Moment 原作者不能再创建第二份“补充视角”；原始 Moment 已代表其视角。

### 4.3 Reaction

`MomentReaction` 包含 Moment、用户、类型、可选短文本和时间。读取和写入前必须先验证当前用户能够看到对应 Moment。

### 4.4 Daily Question

`DailyQuestion` 包含情侣关系、自然日、问题文本、来源 `ai | fallback`、生成上下文版本和时间。`DailyAnswer` 包含问题、用户、答案和提交时间。关系和自然日唯一约束保证同一天只有一个问题；问题和用户唯一约束保证每人只有一个答案。

## 5. DDD 包职责

- `domain/moment`：空间、可见性、Perspective、Reaction 及不变量。
- `application/moment`：三个空间查询、发布、分享、回应、补充视角和回忆查询用例。
- `domain/together`：DailyQuestion、DailyAnswer、解锁规则。
- `application/together`：获取今日问题、提交答案、查询解锁结果；定义 `QuestionGenerator` 端口。
- `infrastructure/persistence/mysql`：新增字段与表的仓储实现，所有查询显式包含访问范围条件。
- `infrastructure/ai`：实现 `QuestionGenerator`，负责调用可替换的模型提供方、超时、输出验证和降级。
- `interfaces/http`：只负责请求转换、认证信息获取、调用用例和响应映射，不承载权限判断。
- `bootstrap`：装配仓储、AI 实现、题库降级器和 HTTP handler。

依赖方向继续保持 `interfaces → application → domain`，基础设施实现 application 定义的端口。

## 6. 数据库设计与迁移

在 `moments` 增加 `space_type`、`visibility`、`kind`、可空 `source_moment_id` 和可空 `daily_question_id`。新增：

- `moment_perspectives`
- `moment_perspective_photos`
- `moment_reactions`
- `daily_questions`
- `daily_answers`

历史数据全部迁移为 `shared + couple`。迁移必须先填充默认值，再增加非空与检查约束，保证旧数据数量、作者、照片和时间不变。回忆推荐实时查询已有 Moment，不建立重复内容表。

## 7. API 设计

### 7.1 Moment

- `POST /v1/moments`：新增 `spaceType`、`visibility`。
- `GET /v1/moments?space=shared`：共同空间。
- `GET /v1/moments?space=personal&owner=me`：我的空间。
- `GET /v1/moments?space=personal&owner=partner`：TA 的空间。
- `PATCH /v1/moments/:id`：作者修改内容或个人记录可见性。
- `POST /v1/moments/:id/share-to-couple`：从个人记录生成共同记录。
- `POST /v1/moments/:id/reactions`：创建或更新回应。
- `DELETE /v1/moments/:id/reactions/:reactionId`：撤回自己的回应。
- `PUT /v1/moments/:id/perspective`：创建或更新自己的补充视角。
- `DELETE /v1/moments/:id/perspective`：删除自己的补充视角。
- `GET /v1/memories/resurface`：获取当前空间可见的回忆候选。

### 7.2 Daily Question

- `GET /v1/daily-question`：返回当天问题、本人的回答状态和是否已解锁；解锁前不返回对方答案。
- `PUT /v1/daily-question/answer`：幂等提交或在解锁前更新本人答案；解锁后拒绝修改。
- `GET /v1/daily-questions`：分页查看历史问题与可见答案。
- `PUT /v1/notification-preferences`：在现有通知偏好中增加 `aiPersonalizationEnabled` 开关。

所有资源详情、图片读取授权和上传确认必须复用同一可见性策略，不能仅在列表接口过滤。

## 8. AI 生成与隐私

AI 上下文只来自：

- 共同空间中双方可见的小事。
- 双方主动标记为 `partner` 的个人小事。

永不使用：

- `private` 小事。
- 原始照片或照片 URL。
- 精确经纬度。
- Access Token、密钥、上传签名和其他凭证。

后端先把允许内容压缩成主题、宽泛情绪、相对时间和非精确场景摘要，再发送给模型。AI 调用设置短超时并限制输出为单个、适合情侣双方回答、无诊断或冒犯内容的问题。请求和响应日志不记录原始上下文。

生成采用“首次请求当天问题时创建并缓存”的方式；数据库唯一约束与事务处理并发首开。AI 调用超时为 3 秒，失败时在同一请求内返回题库问题，并记录可观测但脱敏的失败类型。

首个实现使用 OpenAI-compatible HTTP 协议，通过 `AI_BASE_URL`、`AI_API_KEY` 和 `AI_MODEL` 配置具体提供商，不在领域或 application 层绑定厂商。任何配置缺失都视为 AI 不可用并直接走题库降级。

## 9. 前端结构

新增或提取以下组件：

- `space-switcher`
- `visibility-picker`
- `moment-card`
- `privacy-badge`
- `reaction-bar`
- `perspective-panel`
- `daily-question-card`
- `memory-resurface-card`

页面继续通过 `services/` 调用 API，通过 `store/` 保存当前空间、时间线分页状态和每日问题状态。纯权限显示、卡片组合和动效降级逻辑放在 `utils/`，便于 Node 测试。只按需借鉴 TDesign MiniProgram 或 Vant Weapp 的弹层、上传、日历和无障碍模式，不整体替换现有视觉体系。

## 10. 权限与关系变化

- 作者始终拥有自己的个人记录。
- 当前伴侣只能读取 `partner` 记录，不能编辑或删除。
- 陌生用户不能读取任何个人或共同记录。
- 解绑后，双方立即失去对方个人空间、未完成每日问题和历史 `partner` 内容的访问。
- 解绑后，共同记录保留在数据库中但不再通过当前关系接口返回；重新绑定其他伴侣不会继承旧关系记录。个人源记录始终归作者，不受关系变化影响。
- “以 TA 视角查看”必须调用后端真实权限查询，不能由前端本地过滤模拟。

## 11. 错误处理

- 非法空间与可见性组合返回稳定业务错误。
- 无伴侣时访问 TA 空间、共同分享、双视角或每日问题，返回可操作提示。
- 连续点击通过数据库唯一约束和幂等用例避免重复数据。
- AI 失败不向用户暴露提供商错误，自动降级题库。
- 图片上传完成但业务保存失败时沿用现有补偿或过期清理策略。
- 已解绑关系中的并发写入必须在事务内再次验证关系状态。

## 12. 测试与验收

### 自动化测试

- Domain：全部空间/可见性组合、双视角上限、回答解锁规则。
- Application：本人、当前伴侣、陌生人、解绑后的读取和写入权限。
- Persistence：每个查询都包含正确访问范围；迁移前后历史数量一致。
- AI：成功、超时、无效输出、敏感输出、关闭开关和题库降级。
- HTTP：空间查询、发布、分享、回应、双视角、每日问题和回忆接口。
- 前端：空间切换、默认选择、隐私提示、双向解锁、动效降级和分页隔离。

### 手工验收

- 两个真实账号分别验证共同、仅自己和对方可见内容。
- 单人测试模式验证本人空间，但不得绕过伴侣可见权限。
- 真机验证九图上传、双视角三图、弱网重试和返回页面状态恢复。
- 解绑后立即验证双方无法继续访问对方个人内容。
- AI 不可用时首页仍在可接受时间内展示题库问题。
- 开启减少动态效果后无循环漂浮、旋转和弹跳。

## 13. 实施顺序建议

1. 数据库迁移、领域模型与权限策略。
2. 三个空间的发布和查询闭环。
3. 分享给我们、回应和双视角。
4. 每日一句、AI 适配器与题库降级。
5. 那天的我们。
6. 统一前端组件和手账漂浮动效。
7. 全量自动化、迁移和真机验收。

每一步都必须保持现有共同时间线可用，不能等到最后才恢复旧功能。

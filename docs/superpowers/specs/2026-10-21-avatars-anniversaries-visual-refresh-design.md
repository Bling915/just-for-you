# 自定义头像、完整纪念日与视觉升级设计

## 1. 背景与目标

“小事成双对”的核心仍是两个人共同记录日常：快速发布文字、照片和位置，查看对方状态，并在共同时间线回看生活。此次升级不改变这一产品主线，而是补齐两个能增强真实感和仪式感的能力：双方各自维护头像，以及更完整的纪念日体验。同时把关键页面升级为“薰衣草相册”视觉，使产品具有更明确的品牌辨识度。

成功标准：

- 双方可以独立上传和更换自己的头像，所有用户露出位置及时同步。
- 首页保留小日记作为主要内容，仅用轻量卡片展示置顶纪念日。
- 纪念日支持完整管理、正计时或倒计时、置顶、封面、详情相框和保存纪念图片。
- 页面在开发者工具与真机上均可用；上传或纪念日加载失败不影响日记主流程。
- 后端继续遵循现有 Go DDD 分层，新增逻辑具有领域边界和自动化测试。

## 2. 范围

### 2.1 本次包含

- 双方各自上传、更换头像。
- 首页、日记卡片和个人页展示真实头像。
- 纪念日创建、编辑、删除、置顶、封面、寄语、正计时、倒计时和年度重复。
- 系统“我们在一起”纪念日。
- 首页展示置顶纪念日。
- 纪念日详情相框与本地 Canvas 高清图片生成、保存。
- 首页、日记卡片、纪念日和个人资料页的薰衣草相册视觉升级。
- 单人测试模式覆盖上述个人可操作功能。

### 2.2 本次不包含

- 农历日期。
- 系统日历同步、订阅消息提醒或推送。
- 情头套装或替对方更换头像。
- 服务端生成或长期保存纪念海报。
- 全部已有页面的一次性重写。

## 3. 产品结构

### 3.1 首页

首页保持“小日记优先”的信息层级：

1. 顶部展示双方头像、昵称和牵手天数。
2. 展示对方当前状态及想念、抱抱、加油互动。
3. 展示一张轻量置顶纪念卡；存在多个置顶项时可横向切换。
4. 最近的小日记是页面主体，保留文字、最多九图、位置、编辑和删除。
5. 发布按钮保持固定、易触达。

纪念日数据获取失败时，首页仅隐藏纪念卡，不阻塞状态和日记内容。

### 3.2 头像

- 用户从“我的”页面点击头像进入编辑。
- 支持微信头像选择和本地相册图片。
- 客户端将图片裁剪为方形、压缩后上传 COS，再提交对象 Key。
- 上传完整成功前继续展示旧头像；任一步失败均不提交半成品状态。
- 新头像在首页双方信息、日记卡片和个人页刷新。
- 双方只能修改自己的头像。

### 3.3 纪念日列表

页面分为置顶区域与全部纪念日。纪念日支持：

- 名称、日期、封面和寄语。
- 累计天数或未来倒数。
- 每年重复。
- 置顶、取消置顶、编辑和删除。
- 系统纪念日不可删除，但允许设置封面、寄语和置顶状态。

排序规则为：置顶优先；倒数项按下次发生时间升序；累计项按日期降序；最后以 ID 保证稳定排序。

### 3.4 纪念日详情与纪念图片

详情页以照片相框为主体，显示标题、核心天数、起始或目标日期和寄语。用户可以切换少量内置相框模板，并通过 Canvas 2D 在本地生成高清图片，预览后保存到系统相册。

本地生成可以降低服务器成本并保护照片隐私。相框模板与页面解耦，以独立组件和纯数据模型维护。相册权限被拒绝时，页面提供明确的设置入口。

## 4. 视觉与交互

采用已确认的“A：薰衣草相册”方向：

- 低饱和薰衣草紫、奶白和少量暖粉构成主色。
- 照片是视觉中心；普通信息使用白卡，重点使用半透明玻璃卡，纪念详情使用相框卡。
- 首页纪念卡使用柔光、轻景深和更有层级的数字排版。
- 日记卡更像相册内页，避免所有内容使用同一类白色圆角容器。
- 页面进入、卡片按压和照片加载使用 140–240ms 轻动效。
- 动效只表达状态连续性，并提供统一的 `reducedMotion` 状态以减少位移和缩放。

GitHub 项目仅用于研究原生小程序的信息层级、液态玻璃、轻动效和 Canvas 海报思路；不复制未知许可代码、品牌素材或视觉资产。

## 5. 领域与数据设计

### 5.1 Identity 上下文

头像归入现有 `identity` 上下文：

- `domain/identity`：用户头像引用及更新约束。
- `application/identity`：申请头像上传、更新资料用例。
- `infrastructure/storage/cos`：对象上传签名与访问 URL 解析。
- `interfaces/http/identity`：HTTP DTO、鉴权和错误转换。

数据库保存稳定对象 Key，不保存临时签名 URL。读取模型在响应时将对象 Key 解析为可访问 URL。

### 5.2 Together 上下文

纪念日继续属于 `together` 上下文。升级后的聚合包含：

```text
Anniversary
├── ID
├── CoupleID
├── Title
├── Date
├── CountMode: elapsed | countdown
├── RepeatsYearly
├── Pinned
├── CoverRef
├── Message
└── SystemKind: relationship | none
```

领域层负责：字段约束、系统纪念日删除限制、日期模式约束及更新行为。应用层负责权限、用例编排和读模型。日期展示值由可测试的日期计算器生成，统一使用用户本地自然日语义，避免页面各自计算导致时区偏差。

### 5.3 数据库迁移

新增迁移文件扩展纪念日字段，并为用户头像所需的对象引用补齐约束或索引。不得修改已经执行的旧迁移。现有记录通过默认值兼容：无封面、无寄语、未置顶，按当前年度重复行为映射计时模式。

## 6. 接口设计

### 6.1 用户头像

- `POST /v1/profile/avatar-upload`：返回头像对象 Key、上传 URL 和必要请求头。
- 现有资料更新接口接受 `avatarRef`，只允许提交当前用户已授权前缀下的对象 Key。

### 6.2 纪念日

- `GET /v1/anniversaries`
- `POST /v1/anniversaries`
- `PATCH /v1/anniversaries/:id`
- `DELETE /v1/anniversaries/:id`
- `POST /v1/anniversaries/:id/cover-upload`

首页读模型增加 `pinnedAnniversaries`，避免客户端额外串行请求。所有写接口验证当前情侣关系及资源归属。

## 7. 客户端组件边界

- `avatar-picker`：选择、裁剪提示、压缩、进度和失败回滚。
- `couple-header`：双方头像、昵称和相伴天数。
- `pinned-anniversary-card`：首页紧凑纪念卡和多项切换。
- `anniversary-card`：列表摘要与操作入口。
- `anniversary-frame`：详情相框视觉。
- `anniversary-poster`：Canvas 数据模型、绘制、导出和保存。

日期计算、排序和海报展示数据转换使用纯函数；页面只负责加载、事件和状态切换。

## 8. 错误处理与隐私

- 头像与封面采用“压缩 → 获取上传凭证 → 上传 COS → 提交对象 Key”；提交前不替换旧数据。
- COS 上传失败允许重试，不重复创建业务记录。
- 纪念卡失败不会把首页整体置为错误状态。
- 图片生成失败提供重试；相册权限拒绝提供 `wx.openSetting` 引导。
- 客户端不得包含 COS 长期密钥，所有上传使用服务端短期签名。
- 情侣数据继续按当前绑定关系隔离；头像是本人资料，只有本人可写。

## 9. 测试与验收

### 9.1 自动化测试

- Go 领域测试：头像引用、纪念日创建与更新规则、系统纪念日保护。
- Go 应用测试：权限、上传申请、置顶、编辑和首页聚合。
- Repository 与 Handler 测试：映射、迁移兼容、HTTP 错误响应。
- 小程序测试：日期计算、跨年与闰年、排序、上传失败回滚、头像视图模型、海报数据模型。
- 完成前运行 Go 全量测试、竞态测试、小程序全量测试和格式检查。

### 9.2 手动验收

- 开发者工具与真机局域网模式均验证。
- 两个真实账号分别更新头像并互相看到新头像。
- 单人测试模式可完成本人头像、日记、纪念日和海报流程。
- 验证无照片、有封面、长标题、当天纪念日、跨年倒数、闰日和多置顶项。
- 验证九图日记、弱网、上传失败、拒绝相册权限及重新授权。
- 验证常见屏幕宽度和安全区，不遮挡底部操作。

## 10. 发布顺序

1. 数据迁移、领域模型和后端接口。
2. 头像上传与全局头像展示。
3. 纪念日管理、详情和首页聚合。
4. 本地纪念图片生成与相册权限处理。
5. 首页、日记、纪念日、个人资料的统一视觉和动效收口。
6. 自动化测试、真机回归和部署检查。

本次升级不提交开发者本地的 `miniprogram/config.js`，避免局域网地址进入版本库。

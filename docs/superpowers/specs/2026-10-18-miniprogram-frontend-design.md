# 「小事成双对」微信小程序前端设计

## 1. 目标与边界

「小事成双对」是一款供情侣共同记录日常、在异地感受彼此陪伴的私密微信小程序。第一版需要在一周内完成可在两台真机运行的 MVP，并与现有 Go API 联调。

前端同时承担学习目标：代码应让主要拥有后端经验、前端经验较少的开发者能够理解、调试和继续迭代。因此第一版不使用跨端框架、复杂状态管理库或过度抽象。

第一版包含微信登录、个人资料、情侣绑定、首页、共同时间线、发布最多九张照片的记录、删除自己的记录、退出登录与解除关系。不包含聊天、评论、点赞、通知、持续定位、公开广场和商业化。

## 2. 技术方案

客户端使用原生微信小程序 JavaScript、WXML 和 WXSS。基础表单、弹窗、Toast、加载等成熟交互选择性使用 TDesign Miniprogram；具有品牌辨识度的状态球、记录卡片、九图选择器、空状态和页面动效自行实现。

该方案兼顾可靠性与独特视觉：不重复造基础控件，也不让产品看起来像通用组件库示例。第一版不引入 TypeScript、Taro、UniApp、Redux 或其他全局状态框架。

建议目录：

```text
miniprogram/
├── pages/                 页面
├── components/            品牌业务组件
├── services/              API 调用
├── store/                 会话和少量全局状态
├── utils/                 请求、日期和错误处理
├── styles/                主题变量与公共动画
├── assets/                品牌图片和本地图标
├── app.js
├── app.json
└── app.wxss
```

`services` 只负责与后端通信和响应解包；页面负责用例编排；组件通过属性和事件通信，不直接发网络请求。Token、当前用户和情侣关系保存在轻量 store 中，需要持久化的会话写入微信本地存储。

## 3. 信息架构与页面

### 3.1 启动与登录

启动页展示品牌标志、名称「小事成双对」和文案“把平凡的小事，慢慢过成两个人的故事”。应用读取本地会话并尝试恢复登录，避免每次启动都闪回登录页。

没有有效会话时展示微信登录按钮。调用 `wx.login` 获取临时 code，再请求后端登录接口。首次登录或资料不完整时进入资料设置页，填写昵称并选择头像。

### 3.2 情侣绑定

未绑定用户进入同一个绑定引导页，可选择创建邀请码或输入邀请码。创建后展示六位邀请码、过期时间和复制按钮；输入邀请码后先展示邀请方信息，再明确确认绑定。

邀请码无效、过期、已使用、自绑和已有关系分别显示可理解的反馈。绑定成功后使用柔和庆祝动效进入首页，不使用夸张粒子特效。

### 3.3 首页

首页顶部根据时间显示问候语。核心区域是一张伴侣状态卡，使用缓慢漂浮的轻立体状态球，展示伴侣最近状态及更新时间。状态为空时邀请对方或自己记录此刻。

状态卡下展示双方最近五条记录。底部或视觉安全区上方提供醒目的悬浮发布按钮。下拉刷新首页数据。

### 3.4 发布记录

发布页包含快捷状态、文字、照片和地点四部分。快捷状态支持“上课中”“想你了”“有点累”；所有字段均可选，但至少填写一项。

照片选择器支持最多九张、预览、删除和拖动排序。客户端先逐张请求上传授权，再使用完全一致的 `Content-Type` 直传 COS；显示整体进度和单张状态。全部上传成功后才请求创建记录。失败照片保留在草稿中，可单独重试；提交期间禁用重复操作。

文字输入显示 500 字计数，地点名称限制 80 字。发布成功后清空草稿、触发轻触反馈并返回刷新后的首页或时间线。

### 3.5 共同时间线

时间线按发布时间倒序展示双方记录，使用游标分页。记录卡标明发布者、相对时间、状态、文字、地点和照片宫格。照片保持选择顺序，点击可全屏预览。

只有自己的记录显示删除入口。删除必须确认，成功后从列表平滑收起；非作者或记录不存在时同步刷新数据。

### 3.6 我的

“我的”页面展示头像、昵称、伴侣关系摘要和设置入口。允许修改资料、退出登录以及解除关系。解除关系使用明确的二次确认，说明解除后双方立即无法查看原时间线；确认成功后清空关系与记录缓存并回到绑定页。

### 3.7 导航

底部导航只有“首页”“时光”“我的”三个入口。发布使用独立悬浮主按钮，不作为第四个普通 Tab，突出其核心行为。

## 4. 视觉系统

最终视觉方向为「薰衣草梦境」：浅色、温暖、治愈、轻立体，强调柔光和呼吸感，浪漫但不过度甜腻。

- 品牌主色：薰衣草紫 `#9D87C1`
- 主文字：灰紫黑 `#403946`
- 页面背景：暖白到淡紫的低对比渐变
- 成功与温暖强调：少量月光黄
- 卡片：半透明暖白、细边框和克制的淡紫投影
- 卡片圆角：24–32rpx；主按钮使用胶囊形或圆形
- 字体：系统字体，通过字号、字重和间距建立层级，不依赖特殊字体文件
- 照片保持自然色，不添加重滤镜

品牌图形和装饰采用柔软、不规则的圆形与轨道，隐喻两个人和共同时间。页面避免大面积高饱和紫、廉价霓虹、传统红色爱心和婚庆感。

## 5. 动效与反馈

- 状态球以 3–4 秒周期轻微呼吸和漂浮。
- 首屏卡片按阅读顺序淡入并小幅上移，不使用夸张弹跳。
- 主按钮按下时轻微缩小，并使用微信轻触反馈。
- 上传进度反映真实网络进度；完成后柔和点亮。
- 删除记录时卡片收起，数据失败则恢复原位置。
- 骨架屏使用低对比淡紫流光，避免大面积旋转 Loading。
- 页面切换遵循微信原生交互，不自制复杂路由动画。

动效不得阻塞操作。低性能设备减少模糊、阴影和同时运动的元素；系统开启减少动态效果时停止装饰性循环动画。

## 6. 数据流与会话

应用启动时读取 access token 与 refresh token，然后并行获取当前用户和情侣关系。access token 失效时，网络层只允许一个刷新请求进行；其他失败请求等待刷新结果后重放，避免并发刷新导致 token 轮换冲突。刷新失败后统一清除会话并回到登录页。

首页与时间线共享记录 DTO 和记录卡组件，但各自维护请求状态。时间线只保存当前关系的数据；解除关系或账号退出时清空用户、关系、首页和时间线缓存。

网络层统一处理后端 `data` 和 `error` 响应，并把稳定错误码转换为界面可理解的消息。页面只对需要特殊交互的错误做分支，例如邀请码过期、单张上传失败和无有效情侣关系。

## 7. 状态与异常体验

每个主要页面必须包含加载、成功、空数据、失败和重试状态：

- 首次加载显示与最终布局一致的骨架屏。
- 空时间线显示治愈插画式图形和“记录第一件小事”入口。
- 普通网络失败保留已有数据，并提供非阻塞提示和重试。
- 登录过期自动刷新；完全失效后解释原因并回登录页。
- 上传失败保留文字、状态、地点和已选照片，不自动清空草稿。
- 无情侣关系时不泄露旧关系记录，直接进入绑定引导。
- 服务端 5xx 提示“服务暂时不可用”，不误导用户修改输入。

## 8. 组件边界

第一版自研以下业务组件：

- `status-orb`：状态球、状态文案和更新时间
- `moment-card`：统一呈现记录及删除事件
- `photo-grid`：1–9 张照片宫格与预览
- `photo-picker`：选择、排序、删除、进度和重试
- `empty-state`：各页面空状态
- `skeleton-card`：首页与时间线骨架
- `floating-compose-button`：发布入口和触感反馈

TDesign 只用于 Button、Dialog、Toast、Loading、Input 等通用交互。页面不得直接复制第三方示例视觉；所有组件颜色、间距和圆角通过项目主题变量统一。

## 9. 安全与隐私

Token 不写入日志，不显示在错误界面。请求仅访问配置的 HTTPS API 域名。照片直传只使用后端签发的短期 URL，发布接口只提交对象键；时间线使用后端返回的短期读取 URL。

前端限制选择数量、类型和声明大小，但服务端仍是最终安全边界。位置信息第一版只保存用户主动填写的地点名称，不持续采集精确坐标。

## 10. 测试与验收

自动化测试覆盖网络响应解包、单次 Token 刷新、日期格式、照片队列、最多九张限制、上传失败保留草稿和时间线分页合并。组件逻辑尽量提取为纯函数测试。

微信开发者工具验收包括编译无错误、控制台无未处理异常、模拟网络失败、切换屏幕尺寸和检查请求。真机验收至少覆盖一台 iPhone 和一台 Android：

1. 两名用户分别登录并设置资料。
2. 创建、预览和接受邀请码。
3. 发布纯文字、纯状态、一张照片和九张照片的记录。
4. 查看首页状态、时间线分页和照片预览。
5. 非作者无法删除，作者删除后双方同步不可见。
6. 单张上传失败后草稿保留且可以重试。
7. access token 过期时无感刷新，refresh token 失效时回到登录页。
8. 解除关系后双方立即无法访问旧数据。
9. 刘海屏和底部手势区域不遮挡内容，主要点击区域不小于约 44px。
10. 状态球与列表动效不影响滚动流畅度。

## 11. 开源参考策略

基础组件参考 TDesign Miniprogram 的交互与无障碍实现；浅色玻璃与层次感可参考 Aqua UI WeApp。只复用许可证允许的代码和思想，并保留依赖许可说明。产品布局、品牌组件、配色和动效由本项目重新设计，不直接复制完整页面。

# 小程序架构说明

## 分层

- `pages/`：页面状态机与导航，只编排用户流程。
- `components/`：薰衣草品牌组件，通过 property 和 event 通信。
- `services/`：HTTP API、登录、关系、记录与照片授权。
- `store/`：会话、草稿、时间线及隐私清理。
- `utils/`：日期、Unicode、分页合并和并发上传队列等纯函数。
- `tests/`：Node 内置测试，覆盖刷新并发、九图边界、失败重试、分页去重与数据隔离。

页面不会根据 COS 对象键拼接公开地址，只展示后端返回的短期私有 URL。上传顺序是：申请授权、使用相同 `Content-Type` PUT 原始字节、所有照片成功、最后创建记录。任一照片失败都不会创建残缺记录。

`app-state` 组合各 store 的清理接口。退出登录清除所有私有数据；解除关系保留当前登录用户，但清除关系、首页缓存、时间线和发布草稿。

## 关键状态

首页区分加载、有内容、空内容、有缓存错误和无缓存错误。时间线只有成功响应后才推进 cursor，连续触底共用同一个请求。网络层的并发 401 共用一次 refresh，再重放原请求。
